ISL Module

This section lists all the enhancements for the ISL module.

Rule-Based Automated Asset Isolation

Efficiently automate asset isolation using rule-based triggers in Vulnerability Management and Detection Response (VMDR).

Benefits:

  • Reduce manual effort.

  • Instantly isolates at-risk assets as soon as the condition is met.

  • Accelerates response time to security risks.

  • Strengthens your organization's overall security posture. This can be done by grouping your most critical assets and automatically isolating them when non-compliance or misconfiguration is detected.

To set Automated Asset Isolation and to know further, see Automate Asset Isolation.



This enhancement also adds the following activity logs in the Administration > Activity Logs tab:

  • ISL request submitted: This log is generated when the targeted asset is isolated.

  • Isolation request skipped as Asset not found: This log is generated when the asset for which the rule is triggered is not eligible for isolation.

PM Module

This section lists all the enhancements for the PM module.

Acquired From Vendor Patch Support

The vendor-acquired patches are now available on the VMDR > Vulnerabilities tab, and you can now directly create a Remediation job including these patches from VMDR. This includes both enabled and non-enabled vendor-acquired patches, allowing you to view patch coverage directly in VMDR.

Earlier, these patches had to be included in the job only through the Patch Management application, but with this enhancement, it is available on the VMDR > Vulnerabilities tab.

You can use the QQL token finding.isQualysPatchable: True on the VMDR > Vulnerabilities to fetch all the patches, including automatic and vendor-acquired patches.

NOTE: To create a Remediation job, ensure that vendor-acquired patches are enabled. Patches that are not enabled are indicated by a Lock icon; selecting these disables the Remediate Now option. For more information, see Enable Vendor Acquired Patches.

In the following image, the Unlock icon indicates the patch is enabled.

The Lock icon indicates a non-enabled patch, as shown in the following image. Selecting a non-enabled patch disables the Remediate Now button.

Support for Linux ARM Architecture Rollback Patching

With this enhancement, you can now perform patch rollbacks for Linux ARM architecture assets. To include the Linux ARM patches in a rollback job, in the Create Linux Rollback Job workflow, go to the Select Patches tab and use the QQL token “patch.architecture: aarch64” to filter the ARM patches.

Patching Support for Mac 26 on M5 Architecture

You can now patch Mac 26 assets running on M5 architecture. You can filter these patches on the Patches listing page using the QQL token patch.supportedOs: `macOS 26 Tahoe` and patch.architecture: arm64`.

UI Addressed Issues

The following reported and notable customer issues are fixed in this release.



Component/Category

Description

PM - Job Linux

An issue occurred in which, although email notifications were set in the Linux deployment job, the emails for the Execution Started and Execution Completed notifications were not received.

This issue is now fixed, and notification emails are received successfully.

PM - Job Windows

An issue occurred where if a deployment job is scheduled at a particular time that fell under the Daylight Saving Time (DST) transition gap, the job was stuck in the Prepared state.

This issue is now resolved, and the job runs at the scheduled time without getting stuck.

PM - Job Windows

An issue occurred when the acquired vendor patches from the VMDR > Vulnerabilities tab were used to create a remediation job. An error occurred while saving the job, and job creation failed.

This issue is now resolved, and we support creating remediation jobs for vendor-acquired patches from the VMDR > Vulnerabilities tab.

PM - Linux_Content

An issue occurred in which the patch published date for Linux patches was shown incorrectly on the Patch > View Details page. This issue is now fixed and the published date is correctly displayed.

PM - Job Windows

An issue was observed in which the Windows default deployment job did not trigger for the newly added asset. This issue is now resolved, and the default job runs on the newly added asset.

PM - Assets

An issue was observed where the missing patches were not displayed on the VMDR > Vulnerabilities > Actions > View Missing Patches. This issue is now fixed, and all the missing patches are displayed.

PM - UI

An issue occurred in which the failed deployment job actions and the pre- and post-action results were not displayed in the Job Results report. This issue is now fixed, and the job action results are displayed in the report.

New or Updated API

New

API Endpoint

/isl/v1/assets/isolation/{action}

Method

POST

Not Applicable

We have introduced a new Isolate and Unisolate Assets API as part of automatic rule-based Isolation. These APIs help you to isolate or unisolate the assets in bulk using tags or individual assets using asset IDs. You must have the Isolation Manager and Isolation User roles to use this API.
